Sequence Parallelism for Long-Context AI Training

Sequence parallelism is a distributed training technique designed to overcome memory bottlenecks when training large language models on long-context inputs. By partitioning input sequences along the token dimension across multiple GPUs, this approach drastically reduces the activation memory required per device. This article explains the mechanics of sequence parallelism, how it distributes activation memory during forward and backward passes, and the specific architectural components it targets to enable massive context lengths in artificial intelligence training.

The Activation Memory Bottleneck

When training transformer models with long sequence lengths, model weights are no longer the primary consumer of GPU memory. Instead, activations—the intermediate outputs saved during the forward pass to compute gradients during the backward pass—dominate memory usage.

Standard tensor parallelism splits weight matrices and heavy matrix multiplications across GPUs. However, certain operations remain replicated across all devices. Specifically, Layer Normalization (LayerNorm), Dropout, and residual connections must process the entire sequence length on every GPU. As context lengths grow into the tens or hundreds of thousands of tokens, the memory needed to store the activations for these replicated operations exceeds single-GPU memory limits.

Splitting the Token Dimension

Sequence parallelism solves this bottleneck by dividing the input tensor along the sequence (token) dimension rather than the hidden dimension. If a training step involves a sequence of \(S\) tokens and a group of \(N\) GPUs, sequence parallelism assigns a contiguous chunk of \(S/N\) tokens to each GPU.

Because operations like LayerNorm and Dropout are independent across tokens—meaning the calculation for token 1 does not require data from token 2—each GPU can compute these operations locally on its assigned token slice. Consequently, the activation memory required for these layers is divided by \(N\), freeing up massive amounts of memory.

Coordinating with Tensor Parallelism

A transformer block contains both token-independent operations (LayerNorm, Dropout) and token-dependent operations (Self-Attention, Multi-Layer Perceptrons). Sequence parallelism works in tandem with tensor parallelism by alternating how data is partitioned across the GPUs throughout the network layers.

To transition smoothly between sequence-parallel regions and tensor-parallel regions, the system relies on two primary collective communication operations:

  1. All-Gather: When moving from a sequence-parallel region (like LayerNorm) into a tensor-parallel region (like Self-Attention), each GPU needs access to the full sequence of tokens to compute attention scores. An All-Gather operation collects the \(S/N\) token chunks from all GPUs so that each device temporarily holds the full sequence \(S\) for the matrix multiplication.
  2. Reduce-Scatter: After the tensor-parallel operation is complete, the output must be returned to the sequence-parallel format before hitting the next Dropout or LayerNorm layer. A Reduce-Scatter operation sums the partial results across GPUs and immediately splits the resulting tensor back along the token dimension into \(S/N\) chunks.

During the backward pass, these operations are inverted. The All-Gather becomes a Reduce-Scatter for the gradients, and the Reduce-Scatter becomes an All-Gather.

Advanced Scaling: Ring Attention and Ulysses

Standard sequence parallelism still requires holding the full sequence length temporarily during the attention calculation, which eventually hits a ceiling at extreme context lengths (e.g., 1 million tokens). Newer variations of sequence parallelism distribute the attention mechanism itself along the token dimension:

  • DeepSpeed-Ulysses: Partitions the input along the token dimension and uses All-to-All communication collectives right before the attention layer. This shifts the partitioning from the sequence dimension to the attention head dimension, allowing each GPU to compute attention for the full sequence, but only for a subset of attention heads.
  • Ring Attention: Arranges GPUs in a logical ring. Each GPU holds a chunk of queries, keys, and values corresponding to its \(S/N\) tokens. To compute attention across the whole sequence, GPUs compute local attention on their current chunk while simultaneously passing their key-value blocks to the next GPU in the ring. This hides communication overhead behind computation and completely eliminates the need for any single GPU to ever hold the full sequence length.

Memory Impact Summary

By distributing the token dimension, sequence parallelism ensures that no single GPU is overwhelmed by the linear or quadratic memory scaling of long sequences. When combined with activation checkpointing and tensor parallelism, it reduces the per-GPU activation memory footprint of a transformer layer to a fraction of its original size, directly enabling the training of next-generation, long-context AI models.
