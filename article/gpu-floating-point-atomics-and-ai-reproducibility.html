GPU Floating-Point Atomics and AI Reproducibility

This article explores the root causes of bit-level non-determinism in artificial intelligence workloads run on Graphics Processing Units (GPUs). Specifically, it examines how the combination of IEEE 754 floating-point math limitations and the unpredictable scheduling of parallel atomic additions leads to slight numerical variations between runs. By reading this overview, you will understand the hardware-level mechanics behind why training the exact same neural network twice on the same GPU can yield slightly different results, complicating exact reproducibility in AI research and production.

The Myth of Associative Floating-Point Math

In standard mathematics, addition is associative, meaning that \((A + B) + C\) always equals \(A + (B + C)\). However, computers do not use infinite-precision real numbers; they use the IEEE 754 floating-point standard to represent numbers in a finite amount of memory (such as 32-bit or 16-bit floats).

Because memory is finite, every floating-point addition requires rounding the result to the nearest representable bit pattern. When you add numbers of vastly different magnitudes, the smaller number's precision can be lost entirely in a phenomenon known as "swamping." Consequently, changing the order in which you add a sequence of floating-point numbers changes where the rounding errors occur, resulting in a slightly different final binary value. Therefore, floating-point addition is not associative.

How GPU Atomic Additions Work

Modern AI relies on GPUs to execute thousands of threads in parallel. During tasks like calculating gradients in backpropagation, many threads often need to add their calculated values to a single, shared memory address (such as updating a specific weight).

To prevent threads from overwriting each other's work, programmers use "atomic additions" (e.g., atomicAdd in CUDA). An atomic operation ensures that a memory location is read, modified, and written back as a single, uninterruptible step. If ten threads try to atomically add a value to the same address simultaneously, the GPU hardware forces them into a queue, processing them one by one.

The Intersection of Parallelism and Non-Associativity

The core issue of non-determinism arises from how the GPU manages this queue. GPUs are designed for maximum throughput, not predictable execution order. Thread blocks and warps (groups of threads) are scheduled dynamically by the hardware based on micro-architectural states, memory controller availability, and even minor fluctuations in clock speeds or thermal throttling.

Because the hardware scheduler is dynamic, the exact order in which parallel threads reach the atomicAdd instruction changes from one microsecond to the next.

  • Run 1: Thread A arrives first, followed by Thread B, then Thread C. The GPU computes \((A + B) + C\).
  • Run 2: Thread B arrives first, followed by Thread C, then Thread A. The GPU computes \((B + C) + A\).

Because floating-point math is non-associative, Run 1 and Run 2 will likely produce results that differ in their least significant bits (the "mantissa").

The Impact on Artificial Intelligence

In deep learning, a difference in the last bit of a single floating-point number seems negligible. However, neural networks perform trillions of calculations across millions of parameters over thousands of training steps.

When a gradient update differs by a single bit in the first training step, that tiny difference alters the weights used in the second step. Because neural networks are non-linear systems, these microscopic differences compound exponentially over time—a computational butterfly effect. By the end of training, two models initialized with the exact same random seed and trained on the exact same data can end up with entirely different weights, slightly different loss curves, and varied predictions.

Achieving Determinism and Its Cost

To achieve exact bit-level reproducibility in AI frameworks like PyTorch or TensorFlow, developers must explicitly disable non-deterministic atomic operations. Frameworks accomplish this by replacing fast atomicAdd reductions with deterministic algorithms, such as fixed-order tree reductions, where threads write their results to temporary memory buffers that are subsequently summed in a strict, predetermined sequence.

While this guarantees that \((A + B) + C\) is always calculated in the exact same order, it removes the speed advantage of hardware atomics, requires more memory, and forces threads to wait on one another. Ultimately, AI practitioners must choose between the maximum speed of non-deterministic GPU execution and the slower, strict guarantee of bit-level reproducibility.
